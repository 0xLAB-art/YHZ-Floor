## The one request that actually matters

**G-1 is the only gap that blocks a stated research objective.** Everything else was either resolved inside the authorised boundary (G-2), explicitly out of scope with justification (G-3, G-6, G-8), blocked by a *negative* authorisation that cannot be granted by request (G-5), or dependent on credentials that are not in scope (G-4).

Concretely, approving G-1 would enable the following, and nothing beyond it:

1. `python3 -m venv sp2027/analysis/acts_next_phase_20261019/stage2_provenance/venv`
2. `venv/bin/pip install in-toto==3.1.0` (pinned version; the wheel and its SHA-256 recorded in the Stage 2 freeze manifest)
3. Translate the **frozen** IAR-B held-out corpus (58 cases, already in the repository) into in-toto links and run the genuine `in-toto verify` CLI, offline, against the genuine `in-toto verify` CLI's own verdict.
4. Compare the in-toto verdict with the frozen Stage01 verdict and with the Stage 1 `full` verdict on the same corpus, under one declared common contract, with every shared guarantee marked `N` and every custom construction marked `[CUSTOM-INSPECTION]`.

That comparison is the only route to a *product-level* result for Objective 3. Without it, Objective 3's status is `BLOCKED_BY_RESOURCE_OR_AUTHORIZATION` and the Stage 2 deliverable is an analysis plus a preregistered comparison design, not an empirical comparison.
