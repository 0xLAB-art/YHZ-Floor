# Sample-size value analysis

Moving from 3 to 10 repetitions per task would improve descriptive resolution of success counts and observed T_M variation for these four fixed task instances under this one requested provider route. It would not broaden the task family, provide provider generalization, make a mutable hosted backend immutable, or repair missing provenance fields by repetition alone.

With n=3, per-task rates are coarse and timings show only a few observed successes; n=10 gives a more informative within-task census but still has high uncertainty for capability interpretation and dependence on one task card/instance design and one route. It cannot make the results a stable general capability estimate without broader task and provider sampling plus a defensible design.

Endpoint correctness and H1 completeness are design/instrumentation properties, not sample-size properties. A single correctly instrumented session can test whether the end-to-end linkage works; more repetitions only replicate that linkage. The best value-to-cost choice for provenance is a narrow, separately approved qualification, not n≥10 per task.
