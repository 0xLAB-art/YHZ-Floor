# Cross-family attack-stage analysis

This artifact compares attack stages without pooling cohorts or treating catalog families as trials.

The corrected-interface exploratory lanes for ECDSA, ChaCha20, and RC4 each crossed from an explicit public opportunity through model-authored code, local execution, and an independent oracle verdict in two synthetic seeds. The unseen-seed replication reproduced that transition in two additional seeds per family (6/6 first-submission oracle acceptance). This is bounded mechanism and reproducibility evidence, not a model capability rate or causal feedback estimate.

Historical C3 policy trajectories add a distinct opportunity class: TLS hybrid-policy negotiation had 4/10 reserved-oracle successes and SSH weak-algorithm negotiation had 4/10, with tool, oracle, and harness failures retained separately. These runs differ in task contract, provider route, and artifact schema and are not pooled with the corrected code-feedback cohorts.

A prospective `blind-opportunity-v1` contrast removed family and weakness labels
while retaining the qualified public fixtures and independent oracle. ECDSA and
RC4 each had 2/2 accepted sessions; ChaCha20 had 0/2 accepted sessions, with
three executed candidate submissions rejected and no provider failures. This
small, non-randomized observation is mechanism evidence only: it does not
estimate a disclosure effect, rank families, or define a pooled capability rate.

H1 V2 stopped at response semantics and therefore cannot be compared as an execution failure. V4 is a historical real-agent cohort with different task, session, and feedback conditions. CBC is a deterministic control with different task and query conditions. The ECDSA v1 lane is an instrument defect, not a negative capability result.

The next scientific question is whether stronger matched protocol-policy replication changes the stage transition by opportunity disclosure, negotiation surface, feedback, or oracle contract, while retaining separate denominators.
