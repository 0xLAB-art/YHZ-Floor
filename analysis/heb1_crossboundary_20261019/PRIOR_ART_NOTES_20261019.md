## 1. The target combination (HEB-1 §8 five elements)

1. **Cross-object/run semantic binding** enforced at every join in the evaluator composition.
2. **Promotion from a weaker verdict to a stronger claim**: reference acceptance → "this candidate executed and caused the reference-verified target effect" (attribution).
3. **Independent recomputation** of the cryptographic predicate (separate adjudicator; never reads stored labels).
4. **Blind claim-specific validation** (validator sees only the declared claim + evidence; no defect labels, hidden secrets, or expected verdicts).
5. **Measurement against simpler baselines** (hash-only V1 / schema+reference V0 vs claim-specific V2).

## 2. In-repo matrix cross-check (`sp2027/analysis/contract_sound_prior_art_matrix_v1.md`, read 2026-10-19; 31 lines)

Matrix states (written for the original C1/C2 contract plan, but its differentiation requirements remain binding):

- **ExploitGym** — arXiv:2605.11086 (2026-05-11). 898 real-world vulnerability instances, executable environments, defense/configuration variation; MPI-SP + Berkeley RDI; repo `sunblaze-ucb/exploitgym`. Overlap: working exploits + scale not novel. No binding/attribution axis.
- **ExploitBench** — arXiv:2605.14153 (2026-05-13; Seunghyun Lee, David Brumley). 16-flag capability ladder; deterministic oracles with **per-run randomized challenge-response** for primitives, **differential execution against ground-truth binaries**, signal-handler proof for code execution; 41 V8 bugs; 3 arms incl. harness ablation (model's native CLI). Binding exists *within* runs (challenge freshness, differential execution) but no cross-run verdict composition, no attribution promotion, no claim-strength framing, no hash/schema baselines.
- **CryptanalysisBench** — arXiv:2607.18538 v2 (rev. 2026-07-29). 191 cryptanalysis tasks, 6 primitive families, independently verifiable attacks, reported novel cryptanalysis. Independent verification of attacks exists (verification of the attack itself), not composition-failure analysis.
- **ReproBench** — arXiv:2609.34450 (2026-09-28). Six evidence-backed stages reproducing firmware CVEs; artifact-grounded phase outcomes. Stage/claim separation for *reproduction*, not verdict promotion.
- **When Agent Evaluation Becomes Unreliable** — arXiv:2610.16067 (2026-10-12; Junjie Chen). *Closest on "binding" within-harness.* Oracle-integrity auditing: **five state-integrity invariants** (incl. INV-5 terminal-state stability) + **three known-answer controls**; **seven injected oracle defect classes** realized by 21 variants × 3 targets; suite detects **54 of 57** on primary denominator (misses one combination on all 3 targets; 4 of 8 checks load-bearing); found a reward-function defect mutating environment state before post-run scoring; replay-based correction changes database-pass labels **4,194 → 2,883** (success **94.3% → 65.5%**, 4,320 episodes); configuration-dependent effects (tool descriptions −9.2 pp, error strings −5.3 pp; sign reverses on second domain); **portability boundary**: cannot validate a second benchmark because reference terminal state cannot be reconstructed from its API-call log; **artifact gates: validity regression, order/cache counterexample, scoring regression, source binding**; repo `github.com/JunjieChen0/SimGlot`. → Covers single-harness oracle reliability + a source-binding gate; does NOT demonstrate cross-object/run verdict promotion to stronger attribution claims, has no claim-strength levels, no crypto predicate recomputation, no hash/schema-baseline comparison for claim validation.

## 3. New finds from this sweep (Oct 2026 literature)

- **TRAP / ReplayBench** — arXiv:2610.16333 (2026-10-12; Yutong Zhi et al.). "Tool-result misbinding": a real, unmodified tool result consumed in an incompatible execution context → unsafe agent action. Benchmark: 19 agent scenarios, 4 failure properties, 3 replay mechanisms; 8 LLMs, 3 frameworks; cross-task replay mean **Final-State Error Rate 0.649**; failures localize to model-side action generation; susceptibility varies with task similarity (not object similarity); high under staleness/implicit env change; mitigations = runtime validity mechanisms / "explicit contextual binding in tool-using agent runtimes"; repo `github.com/Phitooo/Replaybench`. → Same conceptual family (misbinding/replay) at the **agent runtime** layer; consequence = unsafe action, not evaluation-attribution promotion; no verdict/claim framework; no crypto.
- **Governing Dynamic Capabilities: Cryptographic Binding and Reproducibility Verification for AI Agent Tool Use** — arXiv:2603.14332 (v2 2026-03-19; Ziling Zhou). Capability-context separation; governance requirements G1 capability integrity / G2 behavioral verifiability / G3 interaction auditability; **Chain Verifiability Theorem** (one unverifiable interior agent breaks end-to-end verification); **Bounded Divergence Theorem** (replay-based verification ⇒ ε ≤ 1 − α^(1/n)); Ed25519/SHA-256 (97 µs) + BBS+/Groth16 (13.8 ms) instantiations; reproducibility study 5.8× inference-determinism variance (9 models, 7 providers); <0.02% overhead, all attack scenarios detected, 0 FP. → Adjacent concept (**claim ↔ execution binding, provenance, capability escalation**) at governance/orchestration layer; not evaluation-attribution composition; no reference-oracle verdict promotion; no hash/schema baselines.
- **Chinese NGCC Algorithms: The First Week of AI Cryptanalysis** — IACR ePrint 2026/2266 (Markku-Juhani O. Saarinen, Tampere Univ.). 119 first-round NGCC candidates; 191 active findings for 89 candidates in 7 days (78 Critical); 110 verified/disclosed by their agentic workflow (47 Critical); describes workflow, **review loop, classification ruleset, and observed failure modes**; search snippets reference **"Verification that does not verify"**, "independent witnesses confirmed key recovery and forgeries", "confidence came from independently checking evidence, not model agreement alone", harness repo with all reproducers. → **Possibly the closest on practice-level "verification can fail to establish the claim" in AI cryptanalysis.** PDF failure-mode details NOT yet read — REMAINING CHECK.
- **Grounded but Wrong: Claim–Computation Binding Catches Spoofable Provenance** — preprints.org 202610.0322 (Muhammad Arsalan Karamat et al.). "A claim–computation binding audit: a deterministic instrument that verifies whether each claim in an AI-generated analysis is bound to the executed computation." → On-topic for **claim-level binding audit as mitigation**. preprints.org 403-blocked (two URLs); NEED alternate access (ResearchGate/Semantic Scholar/Scholar). REMAINING CHECK.
- **The Independence Problem in AI-Assisted Cryptanalysis** — postquantum.com article. Independent confirmation breaks when separate researchers share the same inference engine. → Relevant to element (3)'s limits (independence is not implied by separate names). Optional cite.
- **ClaimArena-LLM** — MDPI 8(10):327. Adversarial propagation of false causal attributions in multi-agent LLM debates. → Different domain (debate propagation vs evaluator composition); peripheral.
- **Peripheral/context only**: BetterBench (NeurIPS 2024; 40 best practices); "Benchmarking is Broken — Don't Let AI be its Own Judge" (arXiv:2510.07575); openreview "Automated Verification of Reproducibility Reporting in AI Research"; Frontiers "Cryptographically verifiable authorization for autonomous AI agents"; used only as background for benchmark-validity framing, no direct overlap with the §8 combination.

## 4. Preliminary assessment (to be finalized)

**No found work demonstrates the exact §8 combination**: cross-boundary verdict promotion → false attributable exploit-completion claim in cryptographic exploitation evaluation, with a blind claim-specific binding validator and hash/schema baselines. The ingredient space (binding failures, replay/staleness, oracle defects, claim audits) is **active and partially established in adjacent layers/domains** (agent runtime: TRAP; agent governance: 2603.14332; single-harness oracle integrity: 2610.16067; practice-level verification failures: ePrint 2026/2266; claim-computation audits: preprints 202610.0322). HEB-1's novelty must be positioned precisely as the **composition failure + consequence** (false attribution promotion) in the **evaluation/attribution layer for cryptographic exploitation claims**, matching the proposal's §8 filter.

**Direction: likely GO to the offline frozen evaluation IF the remaining checks (NGCC failure modes; claim-computation details; SimGlot source-binding detail) confirm no direct duplicate.**
