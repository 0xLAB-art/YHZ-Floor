# One argument from the retained experiments

The author's correction is adopted: connect the existing experiments into a scientific account of AI cryptographic attack capability. This revision does not substitute a request for more experiments for that task.

The organizing question is: **how does an agent's generated program become a verified compromise of a cryptographic system?**

The evidence path is **program construction -> interaction with an exposed relation/interface -> system outcome -> checked recovery**. Execution conditions and operational effort accompany the path. This is an explanatory organization of different studies, not a claim that every cohort is a matched arm of one experiment.

## Narrative consequences

The introduction explains the shared path before presenting individual results. The results follow construction, system exposure, checked recovery, effort and execution linkage. The synthesis derives findings through those same links. Protocol and leakage studies are not detached appendages; they explain the system side of the attack path. Calibration and provenance controls explain what can be inferred from its timing and outcome records.

The numerical units remain explicit: generated programs, sessions, oracle queries, handshakes, timing observations, recovered bytes and diagnostic ratings are never summed into one sample count. This allows all experiment families to contribute without claiming that they measure an identical construct.
